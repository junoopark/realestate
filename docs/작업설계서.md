# 작업 설계서 — 부동산 지표 대시보드

> 작성일 2026-09-30
> mypage 프로젝트의 뼈대를 옮겨 시작했다. 이 문서는 진행하면서 계속 채운다.

---

## 1. 목표

주요 부동산 지표를 한 화면(3 x 2 타일)에 모아 보여준다. 데이터는 백엔드가 ECOS·FRED 등 외부 API에서 받아 가공해 전달한다.

## 2. mypage 에서 가져온 것 / 가져오지 않은 것

| 구분 | 가져옴 | 가져오지 않음 |
|---|---|---|
| 프론트엔드 | 헤더·내비게이션, 다크모드, 한/영 전환, 3 x 2 타일 틀, API 연동 실습 페이지 틀, 색상 토큰 | 프로필·전망·전략·언론 타일과 그 스타일, 프로필 사진, `data/*.json` |
| 백엔드 | FastAPI + CORS 구성, `/health`, 메모리 TTL 캐시, ECOS·FRED 클라이언트(시리즈 목록은 비움), db/crud 자리 | 프로필·방명록·전략 라우터 |
| 데이터베이스 | 폴더 구조와 계획(README) | `schema.sql`, `seed.sql`, `seed/*.csv` 전부 |
| 기타 | `.gitignore`, README 틀 | `scripts/build_*.py` (프로필·언론 전용) |

## 3. 설계 결정

| # | 결정 | 이유 |
|---|---|---|
| D1 | 모노레포 — 저장소 하나에 `frontend/`, `backend/` | mypage와 같은 배포 방식(Vercel·Render Root Directory) |
| D2 | 프론트는 순수 HTML/CSS/JS (빌드 없음) | mypage 틀을 그대로 쓴다 |
| D3 | 지표는 `CATALOG` 한 곳에 등록하고 `/indicators/{key}` 하나로 조회 | 지표가 늘어도 라우터를 새로 만들 필요가 없다 |
| D4 | 처음에는 DB 없이 외부 API + 메모리 캐시 | 부동산 지표는 주·월 단위라 캐시로 충분하다. API가 없는 자료가 생기면 DB를 붙인다 |
