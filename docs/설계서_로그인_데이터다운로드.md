> 작성일 2026-10-17 · 상태: **결정 확정 (2026-10-17) · 코드 작업 전**
> 대상: `frontend/` (Vercel, 빌드 없는 HTML/JS), Supabase(Auth + DB). Render 백엔드는 바꾸지 않는다.

## 1. 목표

| # | 기능 | 완료 기준 |
|---|---|---|
| F1 | 머리띠 오른쪽 위 **Google 계정 로그인** | 5개 페이지(index·policies·learn·about·demo) 어디서나 로그인·로그아웃, 새로고침·페이지 이동 후에도 로그인 유지 |
| F2 | 데이터 차트 오른쪽 위 **엑셀 아이콘 → 데이터 내려받기** | 차트에 보이는 기간·지역·값 그대로 `.xlsx` 파일 저장 (데이터 시트 + 출처 시트) |

## 2. 현재 구조에서 붙일 자리

| 항목 | 현재 | 붙일 곳 |
|---|---|---|
| 머리띠 | 5개 페이지 HTML에 같은 `<header class="site-header">`, 오른쪽 `.header-right` 안에 메뉴 + 테마 버튼 | 테마 버튼 옆에 로그인 영역 `#auth-slot` (각 HTML에 빈 자리 한 줄, 내용은 JS가 채움) |
| 차트 | 모든 시계열 차트가 `js/charts.js`의 `figure()`로 그려짐 (`figcaption.fig-title` + `.fig-plot`) | `figure()` 안에서 캡션 오른쪽 위에 내려받기 버튼 추가 → 대시보드 차트 전체에 한 번에 적용 |
| 차트 데이터 | `figure(opts)`에 `periods`, `series[{name, values}]`, `source`가 이미 들어옴 (값은 `data/factor_sample.json`) | 같은 `opts`로 파일 생성. 나중에 Supabase API로 바꿔도 내려받기 코드는 그대로 |
| 설정 | `js/config.js`에 API 주소 | Supabase URL·anon key(공개용) 추가 |
| Supabase | R-ONE 테이블(RLS 켜짐, 공개 정책 없음) | Auth(Google) 켜기 + `activity_logs` 테이블(본인 기록 쓰기만 허용) |

## 3. 전체 흐름

```
[브라우저]
  ├─ 로그인 버튼 ─▶ Supabase Auth ─▶ Google 동의 화면 ─▶ Supabase 콜백 ─▶ 원래 페이지로 복귀
  │                    (세션은 브라우저 localStorage, supabase-js가 자동 갱신)
  │
  ├─ 로그인 완료 ──┬─▶ Supabase: activity_logs insert (event=login)      ← RLS: 본인 user_id만
  │               └─▶ Vercel:   va('event', {name:'login'})
  │
  └─ 엑셀 아이콘 ──┬─ 로그인 안 됨 → "로그인 후 내려받을 수 있습니다" + 로그인 버튼
                  └─ 로그인 됨 → 파일 생성(브라우저) → 저장
                         ├─▶ Supabase: activity_logs insert (event=download, 차트·지역·행 수)
                         └─▶ Vercel:   va('event', {name:'download', data:{chart, view, rows}})
```

- 파일은 **브라우저에서 바로 만든다**. 서버 왕복이 없어 Render가 잠들어 있어도(30~60초) 내려받기가 지연되지 않는다.
- 로그 쓰기는 **supabase-js가 Supabase에 직접** 한다. Render를 거치지 않는다.

## 4. 설계 결정

| # | 결정 | 이유 | 대안 |
|---|---|---|---|
| D1 | 인증은 **Supabase Auth의 Google 공급자** | DB와 같은 곳에서 사용자 ID(`auth.uid()`)가 나와 RLS로 로그를 보호할 수 있다. 직접 OAuth 서버를 만들 필요 없음 | Google Identity Services 직접 연동 → 사용자 검증·세션을 백엔드에 따로 구현해야 함 |
| D2 | **내려받기는 로그인한 사용자만** | 로그에 "누가" 받았는지 남기는 것이 목적. 익명 쓰기를 열지 않아도 되므로 RLS를 `authenticated`로만 열 수 있다(스팸 기록 방지) | 익명도 허용 → 익명 기록은 FastAPI 경유로만 써야 안전 (Render 지연·구현 증가) |
| D3 | 로그는 **프론트 → Supabase 직접 insert**, 정책은 `user_id = auth.uid()`인 행만 쓰기 | 서버 코드 없이 위조 불가(다른 사람 이름으로 못 씀). 조회 정책은 열지 않음 | FastAPI `/logs` 경유 |
| D4 | 파일 형식 **`.xlsx`와 CSV 둘 다**. 아이콘을 누르면 형식 선택 메뉴. `.xlsx`는 SheetJS를 첫 선택 때만 불러옴, CSV는 UTF-8 BOM으로 라이브러리 없이 생성 | `.xlsx`는 출처·전처리 방법을 둘째 시트에 담고, CSV는 다른 도구에서 바로 읽기 쉬움. 페이지 첫 로딩은 무겁게 하지 않음 | 한 형식만 제공 |
| D5 | Vercel Analytics는 **HTML 스크립트 방식** (패키지 설치 없음) | 빌드 없는 사이트 구조 유지. 5개 HTML `<head>`에 스니펫 추가 | — |
| D6 | **Supabase 로그가 원장**, Vercel은 방문 통계 | 현재 Vercel **Hobby** 요금제라 커스텀 이벤트는 집계되지 않는다(Pro·Enterprise 전용). 이벤트 호출 코드는 넣어 두어 Pro로 올리면 바로 집계된다. Supabase는 사용자별·건별 기록 | — |
| D7 | 개인정보는 **user_id(UUID)만** 로그에 저장. 이메일·이름은 `auth.users`에만 | 로그 테이블 유출 시 노출 최소화. Vercel 이벤트에는 사용자 식별값을 절대 넣지 않음 | — |

## 5. 화면 설계

### 5.1 로그인 (머리띠 오른쪽, 테마 버튼 왼쪽)

| 상태 | 표시 | 동작 |
|---|---|---|
| 로그인 전 | `[G] 로그인` 작은 버튼 (머리띠 버튼색 `--masthead-btn`) | 클릭 → Google 로그인 → 같은 페이지·같은 `#탭`으로 복귀 |
| 로그인 후 | 원형 프로필 사진(없으면 이름 첫 글자) | 클릭 → 작은 메뉴: 이름·이메일, `로그아웃` |
| 처리 중 | 버튼 비활성 + "로그인 중…" | |
| 실패 | 머리띠 아래 한 줄 안내 "로그인하지 못했습니다. 다시 시도해 주세요." | 로그에는 남기지 않음(사용자 ID 없음) |

- 900px 미만에서는 메뉴가 둘째 줄로 내려가므로, 로그인 버튼은 아이콘만 보이게 줄인다.
- 키보드 접근: 버튼·메뉴 모두 Tab/Enter/Esc 지원, `aria-expanded` 표시.

### 5.2 차트 내려받기 (차트 제목 줄 오른쪽 끝)

- 초록색 스프레드시트 모양 아이콘 버튼(인라인 SVG, 18px). 마우스를 올리면 "데이터 내려받기". 누르면 작은 메뉴: `엑셀(.xlsx)` · `CSV`.
- 로그인 전 클릭 → 버튼 옆 작은 말풍선 "로그인 후 내려받을 수 있습니다 [로그인]".
- 파일 이름: `KHMI_<변수ID>_<차트제목>_<지역>_<YYYYMMDD>.xlsx|.csv` (예: `KHMI_V001_월세통합가격지수_서울-경기-부산_20261017.xlsx`)
- CSV는 `데이터` 시트 내용만 담고, 맨 위 주석 줄 없이 머리글부터 시작한다(출처는 파일 이름과 사이트 표기로 대신).

| 시트 | 내용 |
|---|---|
| `데이터` | 1열 `기간`(YYYY-MM 또는 YYYY), 2열부터 지역별 값. 화면의 보기 설정(기간 3년/5년/전체, 수준/전년동기 대비)을 그대로 반영. 잠정값은 별도 열 `잠정` 표시 |
| `정보` | 차트 제목·부제, 단위, 출처(`R-ONE A_2024_00054` 등), 전처리 방법, 공표 시기, 내려받은 시각(KST), 사이트 주소 |

- 적용 범위: `figure()`로 그리는 모든 시계열 차트(Overview·6개 동인·Home 시장 동향 차트). Home의 시도 지도 히트맵은 이번 범위에서 제외(별도 표 형태라 후속 작업).

## 6. Supabase 설계

### 6.1 Auth 설정 (대시보드에서 사람이 할 일 — 8장 체크리스트)

- Authentication → Providers → **Google** 켜기, Google Cloud OAuth 클라이언트 ID·Secret 입력
- Authentication → URL Configuration
  - Site URL: `https://www.khmi.kr`
  - Redirect URLs: `https://www.khmi.kr/**`, `https://khmi.kr/**`, `https://realestate-junoo1.vercel.app/**`, `http://127.0.0.1:5500/**`, (미리보기용) `https://*-junoo1.vercel.app/**`

### 6.2 로그 테이블 (`database/migrations/003_activity_logs.sql`)

```sql
CREATE TABLE IF NOT EXISTS activity_logs (
    id          BIGSERIAL PRIMARY KEY,
    occurred_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    user_id     UUID NOT NULL DEFAULT auth.uid() REFERENCES auth.users(id) ON DELETE CASCADE,
    event       VARCHAR(20) NOT NULL CHECK (event IN ('login', 'logout', 'download')),
    page        VARCHAR(60),            -- 'index.html#rental' 처럼 경로+탭
    target      VARCHAR(80),            -- 내려받기: 변수 ID·차트 키 (예: 'V001:sido')
    detail      JSONB NOT NULL DEFAULT '{}'::jsonb,  -- {format, rows, regions[], range, view}
    session_id  VARCHAR(40),            -- 브라우저 탭 단위 임의 값 (같은 방문 묶기용)
    user_agent  VARCHAR(200)
);
CREATE INDEX IF NOT EXISTS ix_activity_logs_time ON activity_logs(occurred_at DESC);
CREATE INDEX IF NOT EXISTS ix_activity_logs_user ON activity_logs(user_id, occurred_at DESC);

ALTER TABLE activity_logs ENABLE ROW LEVEL SECURITY;
-- 로그인한 사용자는 '자기 user_id' 행만 추가할 수 있다. 조회·수정·삭제 정책은 만들지 않는다.
CREATE POLICY activity_logs_insert_own ON activity_logs
    FOR INSERT TO authenticated
    WITH CHECK (user_id = auth.uid());
-- detail 크기 제한 (악성 대용량 기록 방지)
ALTER TABLE activity_logs ADD CONSTRAINT activity_logs_detail_size
    CHECK (pg_column_size(detail) < 4000);
```

- 관리자 조회는 Supabase 대시보드 또는 DB 소유자 연결(FastAPI·SQL Editor)에서만.
- 집계용 뷰(관리자 전용): 일별 로그인 수, 차트별 내려받기 수, 사용자별 마지막 활동.
- Supabase Auth 자체도 `auth.audit_log_entries`에 로그인 기록을 남긴다. `activity_logs`는 그와 별개로 **앱 동작(내려받기 포함)을 한 곳에** 모으는 용도.

### 6.3 기록 시점

| event | 언제 | target / detail |
|---|---|---|
| `login` | `onAuthStateChange`의 `SIGNED_IN` 중 **실제 로그인 직후 1회** (토큰 갱신·새로고침 복원은 제외) | detail `{provider: 'google'}` |
| `logout` | 로그아웃 버튼 → 기록 후 `signOut()` (순서 중요: 로그아웃 뒤엔 쓰기 권한 없음) | — |
| `download` | 파일 저장 직후 | target `V001:sido`, detail `{format:'xlsx', rows:129, regions:['서울','경기','부산'], range:'5y', view:'level'}` |

- 로그 쓰기가 실패해도 로그인·내려받기 자체는 막지 않는다(콘솔 경고만). 사용자 경험 우선.

## 7. Vercel Analytics 설계

- 5개 HTML `<head>`에 스니펫 추가 (스크립트 경로는 Analytics를 켠 뒤 대시보드에 표시되는 `/<unique-path>/script.js`, 기본값 `/_vercel/insights/script.js`):

```html
<script>window.va = window.va || function () { (window.vaq = window.vaq || []).push(arguments); };</script>
<script defer src="/_vercel/insights/script.js"></script>
```

- 공통 함수 `track(name, data)` 하나로 Vercel·Supabase를 함께 호출(`js/telemetry.js`).

| Vercel 이벤트 | data (문자열·숫자·불리언만, 255자 이하, 개인정보 없음) |
|---|---|
| `login` | `{ provider: 'google' }` |
| `logout` | `{}` |
| `download` | `{ chart: 'V001', scope: 'sido', view: 'level', range: '5y', rows: 129, format: 'xlsx' }` |
| `tab_view` | `{ view: 'rental' }` — 대시보드 탭 이동 |
| `download_blocked` | `{ chart: 'V001' }` — 로그인 전 클릭(전환율 확인용, Supabase에는 기록 안 함) |

- 제약
  - **커스텀 이벤트는 Vercel Pro·Enterprise 전용.** 현재 Hobby라 페이지 방문만 집계되고 이벤트는 무시된다. 이벤트 원장은 Supabase(D6).
  - HTML 방식은 해시(`#overview`, `#rental`) 이동을 별도 페이지뷰로 세지 않는다. 대시보드 탭 이동은 Vercel `tab_view` 이벤트 `{ view: 'rental' }`로 보낸다(Supabase에는 기록 안 함, Pro 전환 시 집계).
  - 로컬(`127.0.0.1`)에서는 스크립트가 없으므로 `va`는 큐에만 쌓이고 전송되지 않는다(정상).

## 12. 위험과 대응
