# 설명변수 추가·수정 가이드

브랜치 `feat/explanatory-variables` 는 **설명변수(X)만** 고쳐 보는 작업 공간이다. 종속변수 Y(V001 월세통합가격지수)는 건드리지 않는다.

## 설명변수가 정의된 곳 (세 군데)

| 무엇 | 파일 | 고칠 때 |
|---|---|---|
| 데이터사전 — 이름·동인·예상 부호·주기·출처 | `frontend/data/drivers.json` 의 `variables[]` | 변수 추가·삭제, 동인 재분류, 부호(`sign`)·설명 수정 |
| 전처리 계열 — 실제 값 | `frontend/data/factor_sample.json` | 직접 고치지 않는다. DFMBA 전처리 엑셀을 고친 뒤 `python scripts/build_factor_sample.py <엑셀>` 로 다시 만든다 |
| Open API 매일 수집 | `backend/app/services/indicator_registry.py` 의 `REGISTRY` | API 로 갱신할 변수를 붙이거나 표·항목 코드를 바꿀 때 (방법은 파일 머리말과 `docs/indicator-pipeline.md`) |

변수 ID(`V0xx`)가 세 곳을 잇는 열쇠다. 새 변수는 세 곳에서 같은 ID 를 쓰고, 동인(`driver`)은 `demand · supply · finance · rental · trigger · macro` 중 하나로 맞춘다.

## 작업 순서

1. 위 파일을 고친다.
2. 보드를 다시 만들고 점검한다.
   ```bash
   python scripts/build_xvar_board.py --strict
   ```
   세 파일 사이에 빠진 ID·다른 동인이 있으면 경고를 내고 실패한다. 통과하면 `docs/설명변수_시계열.html` 을 브라우저로 열어 바뀐 계열을 눈으로 확인한다.
3. 지표 테스트를 돌린다.
   ```bash
   python -m pytest tests/backend/test_indicators.py tests/backend/test_indicator_panel.py tests/backend/test_indicator_kosis.py -q
   ```
4. 커밋하고, 확정되면 `main` 으로 PR 을 연다. 화면(www.khmi.kr)은 DB 를 읽으므로 `factor_sample.json` 을 바꿨다면 합친 뒤 `python scripts/seed_indicators.py` 로 기본 패널을 다시 적재해야 반영된다.
